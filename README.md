# GoalFlow

Менеджер задач с привязкой задач к целям и учётом времени внутри задачи.
Данные хранятся локально в браузере.

**Стек:** Vue 3 (Composition API), TypeScript в режиме `strict`, Vite, обычный CSS.
Зависимостей во время выполнения, кроме Vue, нет.

---

## Запуск

Нужен Node 24 (в проекте есть `.nvmrc`).

```bash
nvm use
npm install
npm run dev        # http://localhost:5173
```

Остальные команды:

```bash
npm run build      # проверка типов и сборка в dist/
npm run preview    # просмотр собранной версии
npm run typecheck  # strict, без any: исходники (vue-tsc) и скрипты (tsc)
npm test           # 55 проверок логики
```

Сборка статическая (`base: './'`), папку `dist/` можно разместить на любом хостинге.

## Как попробовать

Готовый пример (две цели, три проекта, девять задач и неделя истории по времени)
загружается двумя способами:

- **если приложение открыто впервые** — кнопка «Загрузить пример» на приветственном экране;
- **если данные уже есть** — шестерёнка внизу сайдбара → «Загрузить пример».
  Приветственный экран показывается только при полностью пустой базе, поэтому после
  создания первой задачи кнопки на нём уже не будет. Тот же пункт доступен по `⌘K`.

Чтобы вернуться к приветственному экрану, в настройках есть «Удалить все данные»
(удаление можно отменить).

С нуля:

1. `G` — создать цель, например «Запустить продукт до марта», указать дату.
   Изменить или удалить её можно кнопкой с карандашом в строке цели.
2. `P` — создать проект «MVP лендинга» и отметить, какой цели он служит.
3. `N` — быстрый ввод задачи:
   `Написать текст для первого экрана @mvp #текст !высокий ~90м ^завтра`.
   Под строкой видно, как разобраны токены. `Shift+Enter` — добавить и продолжить ввод.
4. Кнопка ▶ в строке задачи запускает таймер. Внизу появляется полоса со счётчиком;
   он переживает перезагрузку страницы. Время задним числом: открыть задачу →
   «Записать время» → `45м`.
5. `/` — строка фильтра. Попробуйте `цель:нет`, `время:>4ч`, `срок:просрочено`,
   `есть:сверхоценки`. Кнопка «Сохранить вид» добавит фильтр в сайдбар.
6. `1`, `2`, `3` — список, доска, календарь. На доске карточки перетаскиваются между
   колонками, в календаре задача перетаскивается на день — так ставится срок.
7. «Время и наблюдения» в сайдбаре — время по дням, целям и проектам плюс блок
   наблюдений. По наблюдению можно кликнуть, оно применит соответствующий фильтр.
8. `E` — выгрузить бэкап. Настройки (`?` или шестерёнка внизу сайдбара) →
   «Восстановить из файла», режим слияния или замены. Там же экспорт в CSV,
   загрузка примера и удаление всех данных с возможностью отмены.
9. AI (необязательно) — Настройки → включить AI → указать ключ Anthropic. Без ключа
   кнопки «Подсказать» работают на локальных эвристиках.

## Решения по ТЗ

### Иерархия: цели → проекты → задачи

Модель плоская и нормализованная: `goals[]`, `projects[]`, `tasks[]`, `timeEntries[]`.
Связи заданы массивами id:

```ts
Task    { projectIds: ID[], goalIds: ID[], … }
Project { goalIds: ID[], … }
```

Следствия:

- **Глубину выбирает пользователь.** Задача может относиться прямо к цели без проекта,
  входить в проект или не иметь ни того, ни другого (раздел «Без разбора»).
  Трёхуровневая иерархия не обязательна.
- **Задача может принадлежать нескольким проектам и целям** — это вопрос из ТЗ,
  решённый массивами вместо одиночных полей.
- **Прогресс цели считается снизу вверх.** Функция `effectiveGoalIds(task)` возвращает
  собственные цели задачи плюс цели её проектов, поэтому цель учитывает всё, что под ней.

Дерево отображается только в сайдбаре — свёрнутым, с процентом выполнения и потраченным
временем в строке цели. Основная область показывает плоский список, сгруппированный по
срочности: «Просрочено», «Сегодня», «Ближайшие 7 дней», «Позже», «Без срока».
Иерархия отвечает на вопрос «где лежит задача», список — «что делать сейчас».

### Учёт времени

- Таймер запускается кнопкой в строке списка, на карточке доски или в карточке задачи.
  Переключаться в другое приложение не нужно.
- Одновременно идёт только один таймер: запуск нового останавливает предыдущий.
- Запуск таймера переводит задачу в статус «в работе», завершение задачи останавливает
  её таймер.
- **Забытый таймер.** Если таймер идёт дольше заданного порога (по умолчанию 90 минут),
  появляется полоса с тремя вариантами: продолжить, записать 90 минут, отбросить сессию.
- **Ручной ввод** в карточке задачи: `45м`, `1ч30м` или `90` плюс дата.
- Сессии короче минуты не сохраняются, чтобы случайный двойной клик не оставлял записей.
- Таймер переживает перезагрузку: в хранилище лежит время старта, а не счётчик в памяти.
- Время показывается на всех уровнях: в задаче (в том числе относительно оценки),
  в заголовке колонки доски, в строке цели, а также в разделе «Время и наблюдения» —
  по дням, по целям и по проектам. Время задачи, принадлежащей нескольким целям,
  делится между ними поровну.

### Минимализм и гибкость

Обязательное поле у задачи одно — название. Проект, цель, теги, срок, оценка, приоритет
и заметка необязательны и не занимают места в интерфейсе, пока не заполнены.

Гибкость обеспечивается синтаксисом быстрого ввода: поля появляются по мере набора.

```
Написать текст для первого экрана @лендинг #текст !высокий ~90м ^завтра
```

| Токен | Значение |
|---|---|
| `@проект` | проект; неизвестный будет предложен к созданию |
| `+цель` | цель |
| `#тег` | тег |
| `!высокий` `!средний` `!низкий` | приоритет |
| `~90м` `~1ч30м` | оценка |
| `^сегодня` `^завтра` `^пт` `^+3` `^2026-10-01` | срок |

Теги нормализуются в нижний регистр и дедуплицируются, в сайдбаре показываются восемь
самых используемых, при вводе работает автодополнение по существующим тегам.

Виды «список», «доска», «календарь» переключаются кнопкой или клавишами `1`, `2`, `3`.
Это разные отображения одной выборки, а не разные структуры данных.

### Фильтры и виды

Вместо набора кнопок используется строка запроса с автодополнением:

```
статус:вработе срок:неделя #дизайн     что в работе на этой неделе по дизайну
цель:нет -статус:готово                задачи без цели
время:>4ч -статус:готово               возможно, работа застряла
есть:сверхоценки                       вышли за оценку
оценка:<30м срок:сегодня               что можно быстро закрыть сегодня
-статус:готово написать текст          поиск по названию и заметкам
```

Правила: клаузы объединяются через «И», повтор одного ключа даёт «ИЛИ»
(`статус:сделать статус:вработе`), префикс `-` инвертирует условие.

Ключи: `статус`, `приоритет`, `цель`, `проект`, `тег`, `срок`, `время`, `оценка`,
`есть`, `создана`. Английские написания (`status`, `due`, `spent` и так далее)
работают наравне с русскими, как и сокращения `ст:`, `пр:`, `ц:`.

Встроено шесть видов: «Сегодня», «Эта неделя», «В работе», «Без цели»,
«Возможно застряли», «Просрочено». Любой фильтр сохраняется как свой вид кнопкой
«Сохранить вид» и появляется в сайдбаре и в палитре команд.

### Хранение и экспорт

Используется `localStorage`, одним JSON-документом под ключом `goalflow.db.v1`.

Выбор обоснован объёмом данных: база на несколько сотен задач занимает около
100–200 КБ при лимите в 5 МБ. Синхронный API убирает слой асинхронности, а весь стор
всё равно держится в памяти как реактивный объект. IndexedDB понадобилась бы при
вложениях или десятках тысяч записей, SQLite через WASM добавил бы мегабайты рантайма
ради запросов, которые выполняет `Array.filter`.

Детали реализации:

- Все даты хранятся как ISO-строки, а не как `Date`. JSON проходит через хранилище,
  экспорт и импорт без шага восстановления объектов.
- Данные при чтении проверяются: всё, что приходит из хранилища или импорта, считается
  недоверенным. Каждое поле проверяется по типу, неизвестное значение заменяется
  умолчанием, ссылка на удалённый проект вычищается. Повреждённый бэкап не роняет
  приложение и не теряется целиком.
- Экспорт: JSON (полный бэкап), CSV задач, CSV лога времени. Ключ API в экспорт
  не попадает.
- Импорт: режим слияния (добавить, существующие id не трогать) или замены. Старый
  вложенный формат экспорта также импортируется.
- Две вкладки синхронизируются через событие `storage`.

Синхронизация между устройствами не реализована: она потребовала бы сервера, аккаунтов
и разрешения конфликтов, что противоречит идее локального хранения. Её роль выполняет
экспорт и импорт файла.

### Горячие клавиши

| Клавиши | Действие |
|---|---|
| `⌘K` / `Ctrl+K` | палитра команд |
| `N` | быстрый ввод задачи |
| `G` / `P` | новая цель / новый проект |
| `/` | фокус в строку фильтра |
| `1` `2` `3` | список / доска / календарь |
| `T` | остановить таймер |
| `E` | выгрузить бэкап |
| `?` | настройки и список клавиш |
| `Esc` | закрыть текущее окно |
| `Shift+Enter` | в быстром вводе: добавить и не закрывать |

Однобуквенные сочетания не срабатывают, когда фокус находится в поле ввода.

Палитра команд ищет команды, цели, проекты, сохранённые виды и сами задачи: задачу можно
открыть или запустить на ней таймер без мыши. Поиск идёт по подпоследовательности символов.

Мышью работает перетаскивание: порядок в списке, статус на доске, срок в календаре.

### AI-помощник

Реализован в два уровня и выключен по умолчанию.

1. **Локальные эвристики** работают всегда и офлайн: разбор формулировки, сопоставление
   с существующими проектами, разбиение задачи на шаги, статистические наблюдения.
   Данные не покидают устройство.
2. **Claude** используется, если пользователь включил AI и указал свой ключ Anthropic.

Без AI приложение работает полностью: все три функции ниже продолжают выдавать результат
на эвристиках, а в интерфейсе он помечен как офлайн-подсказка.

Функции:

| Где | Что делает | Требования промпта |
|---|---|---|
| Быстрый ввод → «Подсказать» | предлагает проект, теги, приоритет, оценку | ответ только JSON; `projectId` только из переданного списка id, иначе `null`; лучше пустое значение, чем слабая догадка |
| Карточка задачи → «Предложить подзадачи» | 3–6 подзадач | ответ только JSON, каждый шаг начинается с глагола и выполним за один подход |
| Время и наблюдения → «Сводка» | отчёт за период простым языком | markdown, без канцелярита, до 300 слов |

Ограничения по назойливости и приватности:

- Результат всегда предлагается к принятию, ничего не применяется автоматически.
- Ошибка сети или ключа приводит к откату на локальный вариант, а не к сообщению об ошибке.
- Ответ модели проверяется: несуществующий `projectId` отбрасывается.
- По умолчанию отправляются только названия, теги и имена проектов. Отправка заметок
  включается отдельным переключателем.
- Ключ хранится только в `localStorage` этого браузера. В файлах проекта его нет, в
  экспорт он не пишется, а бэкапы и `.env` перечислены в `.gitignore`, поэтому в
  репозиторий ключ не попадает. Запрос идёт из браузера напрямую в Anthropic,
  промежуточного сервера нет.
- При выключенном AI все три функции продолжают работать на эвристиках.

## Структура кода

```
src/
  types/index.ts        доменная модель, правило хранения дат
  lib/
    storage.ts          чтение и запись localStorage, проверка и миграция данных
    query.ts            парсер и вычислитель языка фильтров
    capture.ts          парсер строки быстрого ввода
    ai.ts               эвристики, вызовы Claude, проверка ответа
    utils.ts            id, даты, форматирование, склонения
  stores/store.ts       стор: состояние, вычисляемые данные, все изменения
  composables/          useHotkeys
  components/           14 компонентов
  styles/               tokens.css (токены, светлая и тёмная темы) и app.css
scripts/                проверки логики для npm test, со своим tsconfig
```

Стор — модульный singleton, а не фабрика. Один `reactive(db)` на всё приложение, поэтому
сайдбар, доска и таймер работают с одним состоянием. Запись в `localStorage` идёт через
`watch(db, …)` с задержкой 200 мс, вызывающему коду не нужно помнить про сохранение.

Производные данные вынесены в `computed`: `spentByTask`, `visibleTasks`, `goalProgress`,
разбивки времени. Живой таймер обновляется одним общим `now`-ref на всё приложение,
а не интервалом в каждом компоненте.

## Интерфейс

Плотный интерфейс, рассчитанный на клавиатуру: нейтральная палитра, один акцентный цвет,
тонкие границы. Все цвета заданы CSS-переменными. Тёмная тема описана и для
`prefers-color-scheme`, и для атрибута `data-theme`, поэтому переключатель в приложении
перекрывает системную настройку в обе стороны.

Вёрстка mobile-first, три раскладки:

| Ширина | Поведение |
|---|---|
| менее 900px | сайдбар выезжает поверх контента с затемнением, доска скроллится горизонтально |
| 900px и больше | сайдбар — постоянная колонка, доска в три колонки |
| менее 560px | в строке задачи время и кнопка таймера переносятся под название |

Размеры кнопок увеличиваются при сенсорном вводе (`pointer: coarse`), поля ввода на
мобильных имеют размер 16px, иначе iOS увеличивает страницу при фокусе. Горизонтальный
скролл отсутствует начиная с ширины 320px.
